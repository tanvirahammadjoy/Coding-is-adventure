# Phase 1 · M1.4: Control Flow — if/elif/else, match/case, loops

## 1. Learning Objectives

- Write idiomatic conditional and looping code
- Use structural pattern matching (`match`/`case`, PEP 634, Python 3.10+) appropriately
- Understand the (often-missed) `else` clause on loops

## 2. Theory

Python's `if`/`elif`/`else` is standard, but two features deserve deeper treatment:

### `match`/`case` (Structural Pattern Matching, PEP 634, added 3.10)

This is NOT a switch statement — it's **structural pattern matching**, capable of destructuring data (matching on shape, not just value):

```python
match command.split():
    case ["go", direction]:
        move(direction)
    case ["look"]:
        describe_room()
    case ["take", *items]:
        pick_up(items)
    case _:
        print("unknown command")
```

This can match types, destructure sequences/mappings, and bind variables — genuinely different from (and more powerful than) a C-style switch. It exists because dispatching on data _shape_ (common when parsing commands, ASTs, protocol messages) previously required verbose if/elif chains with manual unpacking.

### `for`/`while` ... `else`

The `else` clause on a loop runs **only if the loop completed without hitting `break`**. This is one of Python's most under-used, most-misunderstood features — genuinely useful for "search and act only if not found" patterns, avoiding a manual "found" flag variable.

### WHEN to use match vs if/elif

Use `match` when dispatching on the **shape/type** of data (parsing, protocol handling, AST-like structures). Use `if`/`elif` for simple linear boolean conditions — `match` on a single scalar value with no destructuring is usually not worth the added syntax.

## 3. Visual Explanation

```python
for item in items:
    if item == target:
        found = item
        break
else:
    found = None   # only runs if break was never hit
```

## 4. Real-World Example

Command-line tools and simple protocol parsers (e.g., a Redis-like text protocol handler) commonly use `match`/`case` on tokenized input to dispatch to handlers cleanly, replacing what used to be a long `if isinstance(...)`/`elif isinstance(...)` chain.

## 5. Best Practices

- Use `match` for genuine structural dispatch, not as a novelty replacement for simple `if`
- Use the loop `else` clause for "not found" logic instead of a manual sentinel flag
- Keep conditional chains flat where possible; extract complex conditions into well-named boolean variables or functions

## 6. Common Mistakes

- Using `match` for simple value comparisons where `if`/`elif` reads more clearly
- Forgetting that loop `else` runs on normal completion, not on `continue`
- Deeply nested `if` chains (a code-smell signal to refactor, often via early returns/guard clauses)

## 7. Performance Considerations

`match`/`case` compiles to efficient dispatch (not a linear chain of isinstance checks under the hood for simple cases) — genuinely can be faster than an equivalent long `if/elif isinstance` chain for many-branch dispatch.

## 8. Security Considerations

Command-dispatch patterns (as in the real-world example) are a natural place to validate/sanitize input structure before acting — `match`'s destructuring can double as a lightweight validation layer, but never as a substitute for real input validation on untrusted data.
