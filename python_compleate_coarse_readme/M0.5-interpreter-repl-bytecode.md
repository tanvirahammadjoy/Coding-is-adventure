# Phase 0 · M0.5: The Interpreter, REPL & Bytecode Overview

## 1. Learning Objectives

- Understand the journey from `.py` source to execution
- Use the REPL effectively for exploration
- Read basic bytecode output via the `dis` module

## 2. Theory

Running `python script.py` triggers this pipeline:

1. **Tokenizing** — source text → tokens
2. **Parsing** — tokens → Abstract Syntax Tree (AST)
3. **Compilation** — AST → **bytecode** (a compact instruction set for Python's virtual machine), cached in `__pycache__/*.pyc` for modules (not for the entry script itself, by default)
4. **Execution** — the CPython **eval loop** interprets bytecode instructions one at a time, manipulating a stack-based virtual machine

This is _why_ Python is called an "interpreted" language, though it's more precisely a **bytecode-compiled, then interpreted** language — a common point of confusion. It is NOT compiled to native machine code (unlike C) or run via a full JIT (unlike PyPy, which does JIT-compile bytecode to machine code at runtime).

### `__main__` and script vs import execution

When a file is run directly, its `__name__` is set to `"__main__"`. When imported, `__name__` is the module's name. This is why `if __name__ == "__main__":` guards exist — to let a file be both an importable module and a runnable script without side effects firing on import.

### The REPL

Read-Eval-Print-Loop — `python` with no args. Each expression's value is echoed. Useful for exploration, dangerous as a substitute for tests (nothing typed there is reproducible/saved by default — use a script or notebook for anything worth keeping).

## 3. Visual Explanation

```bash
source.py → [tokenize] → tokens → [parse] → AST → [compile] → bytecode (.pyc for imports)
                                                              → [eval loop] → execution
```

## 4. Real-World Example

Understanding `.pyc` caching explains a classic confusing bug: editing a module, but a stale `__pycache__/*.pyc` (rare, but happens with clock skew or corrupted cache in some deployment pipelines) causes old behavior to persist until the cache is cleared — knowing this pipeline exists makes diagnosing it trivial rather than mysterious.

## 5. Best Practices

- Always guard script entry points with `if __name__ == "__main__":`
- Use the REPL for quick exploration, but move anything worth keeping into a file/test immediately
- Use `python -i script.py` to drop into an interactive session after running a script, for post-mortem exploration

## 6. Common Mistakes

- Writing real logic that only ever runs inside `if __name__ == "__main__":`, making it unimportable/untestable from other modules
- Confusing "interpreted" with "not compiled at all" (there IS a compilation step, to bytecode)
- Relying on REPL history as documentation (it isn't persisted or shareable)

## 7. Performance Considerations

`.pyc` bytecode caching avoids re-parsing/re-compiling unchanged modules on every import — a real (if usually small) startup-time optimization, particularly noticeable in CLI tools invoked frequently.

## 8. Security Considerations

Never `exec()`/`eval()` bytecode or source from an untrusted source — bytecode can be crafted to behave unexpectedly even without matching source, and `eval` of arbitrary strings is a classic injection vector.

## 9. Hands-On Exercises

1. Write a two-function module, import it from the REPL, and inspect `__name__` in both contexts
2. Use `dis.dis()` on a simple function and identify at least 3 bytecode instructions
3. Delete a `__pycache__` folder and observe/time the next import

## 10. Mini Project

Write a small script that uses the `dis` module to compare the bytecode instruction count of two different implementations of the same function (e.g., a loop vs a comprehension) and report which has fewer instructions — a first taste of performance intuition building on real data, not guesswork.

## 11. Interview Questions

- Junior: "Is Python compiled or interpreted?"
- Junior: "What does `if __name__ == '__main__':` do and why?"
- Mid: "What's stored in `__pycache__` and why does it exist?"
- Senior: "Walk me through what happens, step by step, from running `python app.py` to your first line of business logic executing."

## 12. Challenge Exercise

Use `dis.dis` to compare bytecode for `x = x + 1` vs `x += 1` — determine whether they compile identically, and explain why or why not based on what you observe.
